# Definition of Done

A story is Done only when:

- [ ] Acceptance criteria are met and implementation is complete.
- [ ] Necessary engineering design, diagrams and decisions are documented.
- [ ] Appropriate tests are written and passing; actual results are linked.
- [ ] Required CI checks pass.
- [ ] Issue, branch, commits, PR, design and tests form a traceable chain.
- [ ] An independent reviewer approved the PR and conversations are resolved.
- [ ] User/developer documentation and affected architecture are updated.
- [ ] Security and performance impacts are considered and recorded.
- [ ] Stakeholder review is recorded wherever required; pending approval is not acceptance.
- [ ] Meaningful AI assistance is disclosed, or `None` is recorded.
- [ ] Changes are merged into main and iteration/contributor evidence is updated.

The issue milestone identifies the iteration; iteration records link the completion tag and eventual release. Release records link stakeholder feedback and human contribution summaries. Templates alone do not satisfy engineering evidence requirements.
