## Acceptance and records

[#38](https://github.com/ham340i/Industrial-Data-Pipelinen-Platform/issues/38) is the unassigned Release 1 acceptance tracker; it is not a single student’s implementation assignment. Each child issue includes initial points/hours, priority/risk, exact milestone, primary/reviewer, prerequisites, acceptance checkboxes, tailored tests, design links, pending signoff and AI disclosure. Actual branches/commits/PRs/tests must be attached by the owner as produced.

Use [iteration records](releases/README.md), [personal contribution template](individual-contributions/TEMPLATE.md) and [review plan](code-review-plan.md). Keep all approvals, completion boxes, results and benchmarks pending until observed. No `IterationN` or `Release1` tag is created by planning.

Example grounded in planned work: [#8](https://github.com/ham340i/Industrial-Data-Pipelinen-Platform/issues/8) owns the SDK target contract; its issue has a real primary/reviewer and Iteration 1 milestone. Design/code/PR/test evidence is still pending and must not be inferred from this issue’s existence.
