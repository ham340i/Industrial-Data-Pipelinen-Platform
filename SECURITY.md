# Security reporting

No ETL application or supported product release exists yet. Security-sensitive repository issues include exposed credentials, manufacturing datasets and unsafe automation.

Do not post secrets, personal data or sensitive reproductions in public issues. Private vulnerability reporting is enabled: use **Security → Advisories → Report a vulnerability**. If unavailable to you, contact the repository owner through an existing private channel; a dedicated team-approved contact is **TODO**. Do not invent a contact address or publish sensitive details while waiting.

Include affected revision/file, impact, sanitized reproduction steps and a safe way to follow up. No response-time commitment is established yet. On confirmed credential exposure, revoke/rotate first and coordinate removal/history cleanup with the owner.

See the [security plan](docs/security/security-plan.md) for controls and limitations, and the [privacy audit](docs/SOEN490_COMPLIANCE_AUDIT.md#privacy-review) for inspected scope.
